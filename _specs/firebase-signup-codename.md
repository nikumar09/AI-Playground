# Spec for firebase-signup-codename
branch: claude/feature/firebase-signup-codename
figma_component (if used): N/A

## Summary

Wire the existing `AuthForm` component's signup flow to Firebase Authentication using the Firebase Web SDK. On successful account creation, generate a random PascalCase codename from three word lists and set it as the user's Firebase `displayName`. Also create a document in the `users` Firestore collection storing the codename and UID (no email stored).

## Functional Requirements

- `AuthForm` in signup mode (`mode="signup"`) must call `createUserWithEmailAndPassword` from `firebase/auth` using the existing `auth` export from `@/lib/auth`.
- After account creation succeeds, call `updateProfile` on the new user to set `displayName` to a randomly generated codename.
- The codename is generated by picking one word at random from each of three distinct word sets and concatenating them in PascalCase (e.g. `SwiftCrimsonFox`).
- Each word set must contain unique words and be thematically distinct (e.g. adjective / colour / animal, or similar).
- After setting the display name, create a document in the Firestore `users` collection with the document ID equal to the user's UID, containing two fields: `codename` (string) and `uid` (string). The user's email must NOT be stored.
- Firestore must be accessed via the Firebase Web SDK only, using the `app` export from `@/lib/firebase`.
- A `db` Firestore instance should be exported from a new or updated file in `@/lib/` (e.g. `@/lib/firestore.ts`) following the same pattern as `@/lib/auth.ts`.
- While the signup request is in-flight, the submit button should be disabled and show a loading state.
- If Firebase returns an error (e.g. `auth/email-already-in-use`, `auth/weak-password`), display a user-friendly inline error message near the submit button. Do not expose raw Firebase error codes to the user.
- On successful signup, redirect the user to the dashboard (e.g. `/dashboard` or the appropriate authenticated route).
- The codename generation logic should live in a standalone utility function (e.g. `@/lib/generateCodename.ts`) so it can be tested in isolation.

## Possible Edge Cases

- Email already registered — Firebase returns `auth/email-already-in-use`; show a friendly message.
- Weak password rejected by Firebase after passing local validation — show a friendly message.
- `updateProfile` or Firestore `setDoc` fails after account creation — the user account exists but is incomplete; decide whether to surface an error or silently continue. Spec leans toward surfacing an error to prompt retry.
- Network failure mid-request — show a generic error and re-enable the submit button.
- Word lists are empty or have fewer than one word — `generateCodename` should throw or fall back gracefully; in practice the lists are static so this is a compile-time concern.

## Acceptance Criteria

- Submitting the signup form with valid credentials creates a new Firebase Auth user.
- The new user's `displayName` is set to a non-empty PascalCase string made of three words (one from each word set).
- A document exists in Firestore at `users/{uid}` with fields `codename` and `uid`, and no `email` field.
- The submit button is disabled while the request is in-flight.
- A descriptive, human-friendly error message is shown when signup fails (duplicate email, network error, etc.).
- Successful signup redirects the user away from the signup page.
- `generateCodename` is a pure function and can be imported and called without side-effects.

## Open Questions

- What are the exact three word sets to use (adjective / colour / animal, or something else)? A default suggestion is: **Adjectives** (e.g. Swift, Silent, Bold), **Colours** (e.g. Crimson, Jade, Amber), **Animals** (e.g. Fox, Hawk, Wolf). Confirm or replace before implementation.
- Should `updateProfile` / Firestore failures roll back the Auth account, or just surface an error?
- What is the redirect target after successful signup — `/dashboard` or a specific heist list route?

## Testing Guidelines

Create a test file at `./tests/lib/generateCodename.test.ts` and `./tests/components/AuthForm.signup.test.tsx` for the following cases, without going too heavy:

- `generateCodename` returns a non-empty string.
- `generateCodename` output is PascalCase (no spaces, starts with uppercase, contains three capitalised segments).
- `generateCodename` returns different values across multiple calls (probabilistic; run a handful of times).
- `AuthForm` in signup mode renders a submit button labelled "Sign Up".
- Submitting with valid data calls `createUserWithEmailAndPassword` with the correct email and password.
- A Firebase `auth/email-already-in-use` error results in a visible error message in the UI.
- The submit button is disabled while the form is submitting.
